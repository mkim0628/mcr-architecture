# UC-001-비용-인지-메모리-중심-추론-스케줄링

## 개요

### Use Case ID
UC-001

### 제목
비용 인지 메모리 중심 추론 스케줄링

### 설명
워크로드 특성(요청 패턴·토큰 길이·반복성)과 시스템 상태(메모리 계층·용량·비용)를 인지하여, 성능 Cost 모델을 기반으로 KV 캐시와 Load의 배치 정책을 동적으로 결정하고 이기종 메모리 계층에 반영한다. 추론 오케스트레이션의 중심 기능이다.

## 액터

### Primary Actor
서빙 프레임워크 (시스템 액터)
- **역할**: 추론 요청 메타데이터와 KV 캐시 핸들을 전달하고 배치/스케줄 결정을 위임받는다.
- **설명**: vLLM/SGLang 등 MCR Runtime을 호출하는 상위 LLM 서빙 스택.

### Secondary Actor
이기종 메모리 계층
- **역할**: 산출된 배치 결정이 반영되는 대상이며, 상태·용량·비용 텔레메트리를 제공한다.
- **설명**: PIM/PNM·DRAM·CXL·SSD로 구성된 메모리 계층.

## 사전조건

- 성능 Cost 모델이 구성·로드되어 있다. (UC-010)
- 워크로드 특성 및 시스템 상태 텔레메트리가 이용 가능하다. (UC-009)
- 서빙 프레임워크가 추론 요청 메타데이터와 KV 캐시 핸들을 제공한다.

## 사후조건

- 해당 요청에 대한 KV 캐시·Load 배치 결정이 산출된다.
- 배치 결정이 이기종 메모리 계층에 반영된다.
- 배치/스케줄 결정 결과가 서빙 프레임워크에 반환된다.

## 주요 시나리오

1. 서빙 프레임워크가 시스템에게 추론 요청 메타데이터(요청 패턴·토큰 길이·반복성)와 KV 캐시 핸들을 전달하며 배치/스케줄 결정을 요청한다.
2. 시스템은 현재 워크로드 특성과 시스템 상태(메모리 계층·용량·비용)를 조회한다.
3. 시스템은 성능 Cost 모델을 기반으로 KV 캐시·Load의 후보 배치 정책을 평가한다.
4. 시스템은 비용이 최소가 되는 배치 결정을 산출한다.
5. 시스템은 이기종 메모리 계층에 배치 결정을 반영하도록 지시한다.
6. 시스템은 서빙 프레임워크에 배치/스케줄 결정 결과를 반환한다.

## 대안 시나리오

### 3a. 적용 가능한 정책이 복수인 경우
복수의 배치 정책이 적용 가능한 경우.

3a.1. 시스템은 정책 우선순위에 따라 평가 대상을 선택한다.
3a.2. 시스템은 선택된 정책으로 배치 결정을 산출하고 주요 시나리오 4단계로 진행한다.

### 2a. 시스템 상태 텔레메트리가 일부만 제공되는 경우
일부 계층의 상태 정보가 수집되지 않은 경우.

2a.1. 시스템은 이용 가능한 최신 상태 정보를 기준으로 평가를 수행한다.
2a.2. 시스템은 주요 시나리오 3단계로 진행한다.

## 예외 시나리오

### E1. 성능 Cost 모델이 이용 불가한 경우
Cost 모델이 구성되지 않았거나 로드에 실패한 경우.

E1.1. 시스템은 배치 결정을 산출할 수 없음을 판단한다.
E1.2. 시스템은 서빙 프레임워크에 결정 불가 오류를 반환한다.

### E2. 모든 메모리 계층의 가용 용량이 부족한 경우
요청을 수용할 수 있는 계층이 없는 경우.

E2.1. 시스템은 배치 불가 상태를 판단한다.
E2.2. 시스템은 서빙 프레임워크에 용량 부족 오류를 반환한다.
