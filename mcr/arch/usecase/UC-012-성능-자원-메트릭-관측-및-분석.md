# UC-012-성능-자원-메트릭-관측-및-분석

## 개요

### Use Case ID
UC-012

### 제목
성능·자원 메트릭 관측 및 분석

### 설명
처리량·TTFT·오프로딩 비율·재사용률 등 성능/자원 메트릭을 수집하여 모니터링·실험 환경(TestBed/Emulation)으로 내보내고 분석에 활용한다.

## 액터

### Primary Actor
운영자 (연구/플랫폼 엔지니어)
- **역할**: 성능/자원 메트릭을 조회하고 분석한다.
- **설명**: 성능을 평가·분석하는 주체.

### Secondary Actor
모니터링·실험 환경 (MCR TestBed / QEMU Emulation)
- **역할**: 내보낸 메트릭을 수집·저장하는 대상이다.
- **설명**: 성능 평가·검증을 위한 외부 인프라.

## 사전조건

- 운영자가 메트릭 관측 인터페이스에 접근 가능하다.
- 시스템이 성능/자원 메트릭을 산출하고 있다.

## 사후조건

- 요청된 성능/자원 메트릭이 제공된다.
- 메트릭이 모니터링·실험 환경으로 내보내진다.

## 주요 시나리오

1. 운영자가 시스템에게 성능/자원 메트릭 관측을 요청한다.
2. 시스템은 처리량·TTFT·오프로딩 비율·재사용률 등 메트릭을 집계한다.
3. 시스템은 집계된 메트릭을 모니터링·실험 환경으로 내보낸다.
4. 시스템은 운영자에게 관측 결과를 반환한다.

## 대안 시나리오

### 1a. 특정 기간/대상의 메트릭을 요청하는 경우
운영자가 기간·대상을 지정하여 조회하는 경우.

1a.1. 시스템은 지정된 조건에 해당하는 메트릭만 집계한다.
1a.2. 시스템은 주요 시나리오 3단계로 진행한다.

## 예외 시나리오

### E1. 집계할 메트릭이 없는 경우
대상 기간/조건에 해당하는 메트릭이 없는 경우.

E1.1. 시스템은 데이터 부재 상태를 판단한다.
E1.2. 시스템은 운영자에게 데이터 없음 정보를 반환한다.

### E2. 모니터링·실험 환경으로 내보내기에 실패한 경우
외부 환경으로의 전송에 실패한 경우.

E2.1. 시스템은 내보내기 실패를 판단한다.
E2.2. 시스템은 운영자에게 내보내기 실패 정보를 반환한다.
