# UC-004-KV-Cache-계층-배치-결정

## 개요

### Use Case ID
UC-004

### 제목
KV Cache 계층 배치 결정

### 설명
Tiered Memory(PIM/PNM·DRAM·CXL·SSD) 내에서 KV Cache의 최적 Data Placement를 결정하여 TTFT(Time To First Token)를 최적화한다.

## 액터

### Primary Actor
서빙 프레임워크 (시스템 액터)
- **역할**: KV Cache 배치 대상과 컨텍스트를 전달하고 계층 배치 결정을 위임받는다.
- **설명**: MCR Runtime을 호출하는 상위 LLM 서빙 스택.

### Secondary Actor
이기종 메모리 계층
- **역할**: 배치 결정이 반영되는 대상이며, 계층별 상태·용량·비용을 제공한다.
- **설명**: PIM/PNM·DRAM·CXL·SSD로 구성된 메모리 계층.

## 사전조건

- 배치 대상 KV Cache가 존재한다.
- 각 메모리 계층의 상태·용량·비용 정보가 이용 가능하다. (UC-009)
- 성능 Cost 모델이 구성되어 있다. (UC-010)

## 사후조건

- KV Cache의 계층 배치 위치가 결정된다.
- 배치 결정이 이기종 메모리 계층에 반영된다.
- 배치 결정 결과가 서빙 프레임워크에 반환된다.

## 주요 시나리오

1. 서빙 프레임워크가 시스템에게 KV Cache와 그 컨텍스트(크기·접근 특성 등)를 전달하며 계층 배치 결정을 요청한다.
2. 시스템은 각 메모리 계층의 상태·용량·비용 정보를 조회한다.
3. 시스템은 성능 Cost 모델을 기반으로 TTFT 관점의 후보 배치를 평가한다.
4. 시스템은 TTFT가 최적이 되는 계층 배치 위치를 결정한다.
5. 시스템은 결정된 계층에 KV Cache를 배치하도록 지시한다.
6. 시스템은 서빙 프레임워크에 계층 배치 결정 결과를 반환한다.

## 대안 시나리오

### 4a. 최적 계층의 용량이 부족한 경우
TTFT 최적 계층에 가용 용량이 부족한 경우.

4a.1. 시스템은 차순위 계층을 대상으로 배치를 재평가한다.
4a.2. 시스템은 주요 시나리오 5단계로 진행한다.

### 1a. 배치 대상이 다수의 KV Cache 블록인 경우
여러 블록의 배치를 일괄 요청한 경우.

1a.1. 시스템은 각 블록의 접근 특성에 따라 계층 배치를 개별 평가한다.
1a.2. 시스템은 주요 시나리오 4단계로 진행한다.

## 예외 시나리오

### E1. 모든 계층에 배치 가능 용량이 없는 경우
어떤 계층에도 KV Cache를 배치할 수 없는 경우.

E1.1. 시스템은 배치 불가 상태를 판단한다.
E1.2. 시스템은 서빙 프레임워크에 용량 부족 오류를 반환한다.

### E2. 계층 상태 정보를 조회할 수 없는 경우
메모리 계층 텔레메트리 조회에 실패한 경우.

E2.1. 시스템은 배치 결정을 보류한다.
E2.2. 시스템은 서빙 프레임워크에 상태 조회 실패 오류를 반환한다.

## 관련 Use Case

- UC-001 (비용 인지 추론 스케줄링): 계층 배치 결정을 활용
- UC-005 (KV Cache 분류·이동): 배치 후 데이터 성격 변화 시 이동과 연계
- UC-009 (워크로드·상태 모니터링): 계층 상태 입력 제공
- UC-010 (성능 Cost 모델 관리): 평가 기준 제공

## 비고

TTFT 최적화는 본 Use Case가 산출하는 배치 결정의 기능적 목표이다. 배치 결정 알고리즘의 내부 최적화·피드백 루프 설계는 Phase 4·5에서 다룬다.
