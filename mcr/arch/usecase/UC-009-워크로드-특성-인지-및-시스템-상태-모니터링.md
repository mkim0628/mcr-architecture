# UC-009-워크로드-특성-인지-및-시스템-상태-모니터링

## 개요

### Use Case ID
UC-009

### 제목
워크로드 특성 인지 및 시스템 상태 모니터링

### 설명
요청 패턴·토큰 길이·반복성 등 워크로드 특성과 메모리 계층의 상태·용량·비용 텔레메트리를 수집하여, 의사결정(스케줄링·배치·분배)의 입력으로 제공한다.

## 액터

### Primary Actor
서빙 프레임워크 (시스템 액터)
- **역할**: 추론 요청 흐름을 통해 워크로드 특성의 원천을 제공한다.
- **설명**: MCR Runtime을 호출하는 상위 LLM 서빙 스택.

### Secondary Actor
이기종 메모리 계층
- **역할**: 상태·용량·비용 텔레메트리를 제공한다.
- **설명**: PIM/PNM·DRAM·CXL·SSD로 구성된 메모리 계층.

## 사전조건

- 서빙 프레임워크의 추론 요청 흐름에 접근 가능하다.
- 메모리 계층이 상태 텔레메트리를 제공한다.

## 사후조건

- 최신 워크로드 특성과 시스템 상태가 수집·갱신된다.
- 수집된 정보가 의사결정 Use Case가 조회할 수 있도록 제공된다.

## 주요 시나리오

1. 서빙 프레임워크가 추론 요청 흐름을 통해 워크로드 정보를 전달한다.
2. 시스템은 요청 패턴·토큰 길이·반복성 등 워크로드 특성을 산출한다.
3. 시스템은 이기종 메모리 계층으로부터 상태·용량·비용 텔레메트리를 수집한다.
4. 시스템은 수집된 워크로드 특성과 시스템 상태를 갱신한다.
5. 시스템은 의사결정 Use Case가 조회할 수 있도록 최신 상태를 제공한다.

## 대안 시나리오

### 3a. 일부 계층의 텔레메트리만 수집되는 경우
일부 메모리 계층의 상태 정보가 제공되지 않는 경우.

3a.1. 시스템은 수집 가능한 계층의 상태만 갱신한다.
3a.2. 시스템은 주요 시나리오 5단계로 진행한다.

## 예외 시나리오

### E1. 메모리 계층 텔레메트리 수집에 실패한 경우
메모리 계층 상태 조회가 전체적으로 실패한 경우.

E1.1. 시스템은 직전 수집된 상태를 유지한다.
E1.2. 시스템은 텔레메트리 수집 실패를 기록한다.

## 관련 Use Case

- UC-001 (비용 인지 추론 스케줄링): 수집 정보를 입력으로 사용
- UC-004 (KV Cache 계층 배치 결정): 계층 상태를 입력으로 사용
- UC-005 (KV Cache 분류·이동): 분류/이동 판단 입력으로 사용
- UC-008 (연산 자원 분배 결정): 자원 가용 상태를 입력으로 사용
