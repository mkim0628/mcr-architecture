# UC-010-성능-Cost-모델-관리

## 개요

### Use Case ID
UC-010

### 제목
성능 Cost 모델 관리

### 설명
메모리 계층/HW 자원을 추상화한 성능 Cost 모델을 정의·갱신·교정하여, 스케줄링·배치·오프로딩 결정이 참조하도록 한다.

## 액터

### Primary Actor
운영자 (연구/플랫폼 엔지니어)
- **역할**: Cost 모델을 정의·갱신하고 실측/에뮬레이션 결과로 교정한다.
- **설명**: 정책·모델을 구성·튜닝하고 성능을 분석하는 주체.

### Secondary Actor
모니터링·실험 환경 (MCR TestBed / QEMU Emulation)
- **역할**: Cost 모델 교정에 사용되는 실측·에뮬레이션 성능 데이터를 제공한다.
- **설명**: 성능 평가·검증을 위한 외부 인프라.

## 사전조건

- 운영자가 Cost 모델 관리 인터페이스에 접근 가능하다.
- 교정에 사용할 성능 데이터(실측 또는 에뮬레이션)가 이용 가능하다. (갱신/교정 시)

## 사후조건

- 성능 Cost 모델이 정의되거나 갱신된다.
- 갱신된 Cost 모델이 결정 로직(UC-001·UC-004·UC-008)이 참조할 수 있도록 반영된다.

## 주요 시나리오

1. 운영자가 시스템에게 Cost 모델 정의 또는 갱신을 요청한다.
2. 시스템은 입력된 모델 파라미터(메모리 계층·디바이스 비용 특성 등)의 유효성을 확인한다.
3. 시스템은 모니터링·실험 환경의 성능 데이터를 기준으로 모델을 교정한다.
4. 시스템은 갱신된 Cost 모델을 저장한다.
5. 시스템은 갱신된 Cost 모델을 결정 로직이 참조하도록 반영한다.
6. 시스템은 운영자에게 모델 관리 결과를 반환한다.

## 대안 시나리오

### 1a. 신규 디바이스의 Cost 특성을 추가하는 경우
차세대 CXL-PNM/PIM-SSD 등 신규 디바이스를 추가하는 경우.

1a.1. 시스템은 신규 디바이스의 Cost 특성을 모델에 추가한다.
1a.2. 시스템은 주요 시나리오 4단계로 진행한다.

### 3a. 교정용 성능 데이터를 제공하지 않는 경우
운영자가 교정 없이 파라미터만 갱신하는 경우.

3a.1. 시스템은 교정 단계를 생략하고 입력 파라미터로 모델을 구성한다.
3a.2. 시스템은 주요 시나리오 4단계로 진행한다.

## 예외 시나리오

### E1. 모델 파라미터가 유효하지 않은 경우
입력된 Cost 모델 파라미터가 형식·범위에 맞지 않는 경우.

E1.1. 시스템은 모델 갱신을 거부한다.
E1.2. 시스템은 운영자에게 유효성 오류 정보를 반환한다.

### E2. 성능 데이터 조회에 실패한 경우
교정용 실측/에뮬레이션 데이터 조회에 실패한 경우.

E2.1. 시스템은 교정을 중단한다.
E2.2. 시스템은 운영자에게 데이터 조회 실패 정보를 반환한다.

## 관련 Use Case

- UC-004 (KV Cache 계층 배치 결정): Cost 모델을 결정 기준으로 사용
- UC-008 (연산 자원 분배 결정): Cost 모델을 결정 기준으로 사용
- UC-012 (성능·자원 메트릭 관측): 교정 데이터의 원천과 연계

## 비고

본 Use Case는 Cost 모델의 정의·갱신·교정·반영이라는 기능적 동작에 한정한다. 실측(TestBed)과 에뮬레이션(QEMU) 환경 간 모델 일관성을 위한 구조는 Phase 5·6에서 다룬다.
