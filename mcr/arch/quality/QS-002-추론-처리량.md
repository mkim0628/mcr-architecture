# QS-002-추론-처리량

## 개요

### Quality Scenario ID
QS-002

### 제목
추론 처리량

### 설명
동일 자원 기준 End-to-End 추론 처리량. 스케줄링·KV 재사용·오프로딩의 종합 효과를 반영한다.

### 품질 속성
성능 (처리량)

## 환경

### 시스템 상태
MCR Runtime이 서빙 프레임워크와 통합되어 지속 부하(sustained load) 하에 다수 추론 요청을 처리 중이다.

### 초기 조건
- 고정된 연산·메모리 자원 구성이 주어진다.
- 성능 Cost 모델과 정책이 구성되어 있다.

### 부하 조건
동시 다수 요청이 지속적으로 유입되는 포화 부하 상태.

### 관련 컴포넌트
- InferenceScheduler
- KVCacheReuseResolver
- ComputeDispatchPlanner
- ComputeOffloadExecutor
- RetrievalOffloadExecutor

## 동작

서빙 프레임워크가 지속적으로 추론 요청을 전달하면, 시스템은 스케줄링·재사용·연산 분배·오프로딩을 수행하여 요청을 처리하고 토큰을 생성한다. 측정 구간 동안 생성된 총 토큰(또는 완료 요청) 수를 집계한다.

## 측정

- 측정 항목: 처리량 (tokens/s 또는 requests/s)
- 측정 공식:

```
처리량 = [측정 구간 동안 생성된 토큰 수] / [측정 구간 시간]
```

## 관련 문서

- UC-001 (비용 인지 메모리 중심 추론 스케줄링)
- UC-002 (Non-contiguous KV 캐시 재사용)
- UC-008 (연산 자원 분배 결정)
- 컴포넌트: InferenceScheduler, ComputeDispatchPlanner
